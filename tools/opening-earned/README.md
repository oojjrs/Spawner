# Opening and growth rebalance

## Current user-directed baseline
Starting cash30P. First upgrade80P base, with the existing pebble25% discount
making its actual cost60P. Later upgrade candidates are200P and500P base
(pebble150P/375P), a consistent2.5x step. Earlier12P/20P proposals are rejected
and retained only as experimental history, not the current product decision.

The original50P start against20P growth allowed immediate upgrade. Imposing a
120-second click delay did not prove that gathering funded growth. This was a
verification/design error. Old25–43-minute results must not be presented as
validation of this corrected opening.

## Current implementation under validation
Four real17P starter workers per tribe. DNA prices and natural resource map
are unchanged. Each starter uses four genes, nine of19 cells:
bean gather+capacity3; spore gather+capacity2+harvestSpeed;
pebble gather+capacity2+health; spring gather+capacity2+movement.

Basic gathering yields up to2 resources per cycle, still capped by carrying
capacity. An8P gather-only unit with capacity1 still gathers1. A17P hauler with
capacity3 gathers2 per cycle. The45P level-three worker was already capped at4
and is unchanged. This does not double overall income: travel and unloading
remain; theoretical starter throughput improvement is roughly10–21%.
No duplicated gather gene, invalid DNA, hidden starting stat or bonus point
conversion is used. The attempted double-gather design was rejected by normal
validation and discarded, not made legal by weakening the rules.

## Evidence so far
With30P/80P and the old harvest1, only3/12 selected world cases had a soldier
ready before5:00 (all survived8:00). With harvest2,11/12 had one before5:00;
spore13 with30-second decisions finished at5:03.25. These controls used later
prices240/720; they are not labelled final200/500 verification.

Actual-world verification of final80/200/500, including later growth, is ongoing.
79 focused regressions pass, including normal DNA validation, prices, capacity
caps, all growth costs, starter production, upgrade rejection, raid schedule
and previous-save balance preservation. Existing saves retain their balances;
fresh-game timings must not be claimed for old saves.

For the17P blade+power+health soldier, one extra17P worker plus the first soldier
requires84P earned normally or64P for pebble. Two soldiers require101/81P.
Without the extra worker the first soldier needs67/47P.30P permits immediate
worker creation but cannot pay for any tribe's first upgrade alone.

No combat/raid delay was added. The harness records actual birth completion,
not just purchase;0 means five-second polling,15/30 means decisions at those
intervals. It includes actual worlds, rival colonies, movement, resources,
raids and combat but no manual formation/retreat orders. Finite selected cases
are not every map or every human mistake. Final later-game conclusions pending.
