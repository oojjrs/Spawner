군락 Idle 게임 기획 초안

단일 HTML 파일로 실행되는 클라이언트 기반 idle 게임. 중심 군락이 생명체를 생성하고, 유저는 직접 명령 대신 DNA 조작으로 집단의 생존 방식을 설계한다.

문서 상태: 초안 / Design.html
실행 형태: 로컬 HTML
저장: 브라우저 localStorage 우선
개요 핵심 루프 세계와 객체 DNA 조작 Idle 구조 업무 화면처럼 보이는 그래픽 저장과 기술 방향 개발 단계 열린 질문

개요

플레이어는 군락의 지휘관이 아니라 유전자의 편집자다. 군락은 일정 주기마다 생명체를 생성하고, 생성된 생명체는 제한된 수명 동안 자원을 모으거나, 군락을 방어하거나, 다음 세대의 생존 조건을 개선한다.

직접적인 조작은 최소화한다. 클릭으로 유닛을 움직이는 게임이 아니라, DNA 조합을 바꿨을 때 전체 생태계가 어떤 식으로 변하는지 관찰하는 게임에 가깝다.

single-file HTML client-only idle genetic tuning colony simulation

핵심 루프

  1. 군락이 정해진 시간마다 생명체를 생성한다.
  2. 생명체는 DNA, 군락 상태, 환경 조건에 따라 역할과 행동 성향을 가진다.
  3. 각 생명체는 일정 수명을 살며 집단 생존에 기여한다.
  4. 기여 결과가 군락의 자원, 안정도, 번식력, 위험 대응력에 반영된다.
  5. 플레이어는 관찰 결과를 바탕으로 DNA를 조작한다.
  6. 새로운 세대가 바뀐 DNA를 반영하고, 장기적인 군락 성향이 변한다.

짧은 재미

DNA 하나를 바꿨을 때 몇 분 안에 지표 변화가 보여야 한다. “바꿔보고 관찰한다”가 즉각적으로 느껴지는 것이 중요하다.

긴 재미

퇴근 전 켜둔 군락이 몇 시간 뒤 다른 균형점에 도달한다. 완전 방치가 아니라 가끔 확인하면 판단할 거리가 생기는 형태가 좋다.

세계와 객체

요소 초기 정의 상태
군락 중심 생명체 또는 구조물. 생성 주기, 보유 자원, 안정도, 위험도, DNA 프로필을 가진다. 기본
생명체 군락에서 생성되는 일시적 객체. 수명, 에너지, 역할, 행동 성향, 기여 로그를 가진다. 기본
자원 생명체 생성과 DNA 조작에 쓰이는 내부 자원. 이름과 표현은 추후 결정한다. 미정
환경 온도, 포식 압력, 오염, 먹이 밀도 같은 변화 요인. 초기 버전에서는 단순 지표로 처리한다. 후순위

DNA 조작

플레이어의 핵심 행동은 DNA 조작이다. 다만 첫 구현에서는 버튼 몇 개로 수치를 바꾸는 수준에서 시작하고, 이후 유전자 슬롯, 돌연변이, 상호작용을 확장한다.

유전자 후보 영향 트레이드오프
수명 생명체가 활동 가능한 시간 증가 생성 비용 증가 또는 번식 속도 감소
대사 효율 자원 소비 감소, 장기 생존에 유리 순간 기여량 감소
채집 본능 자원 획득률 증가 방어 또는 유지보수 행동 감소
결속 반응 군락 안정도 회복, 위협 대응 강화 개체별 생산성 감소
변이율 예상 밖의 조합과 자동 적응 가능 군락 성향이 불안정해짐
DNA 조작은 “정답 빌드” 하나로 수렴하면 금방 지루해진다. 환경, 비용, 부작용이 함께 움직여서 상황별 최적해가 달라지는 구조가 필요하다.

Idle 구조

브라우저에 켜두는 게임이므로, 플레이어가 계속 보고 있지 않아도 군락은 진행되어야 한다. 단일 HTML 기반이므로 처음에는 탭이 열려 있을 때의 실시간 진행을 우선하고, 이후 마지막 저장 시간 기준의 오프라인 보상을 추가한다.

활성 상태

  • 1초 또는 5초 단위 tick
  • 생성, 사망, 기여량 계산
  • 차트와 로그의 점진적 갱신

비활성 상태

  • 마지막 저장 시각 기록
  • 재접속 시 경과 시간 압축 계산
  • 너무 큰 보상은 상한으로 제한

업무 화면처럼 보이는 그래픽

회사에서 브라우저에 켜두는 형태라면 노골적인 게임 UI보다 관측 대시보드처럼 보이는 방향이 어울린다. 생명체를 귀엽거나 전투적으로 그리기보다, “배양 관측 시스템”, “생체 데이터 모니터”, “군락 안정도 리포트”처럼 표현하면 업무 도구와의 거리감이 줄어든다.

방향 장점 주의점
데이터 대시보드 업무 화면처럼 보이고 idle 게임의 지표 관찰과 잘 맞는다. 너무 건조하면 생명체를 키운다는 감정이 약해질 수 있다.
현미경 관찰판 생명체의 존재감을 은근히 줄 수 있다. 시각적으로 게임처럼 보일 가능성이 커진다.
로그/리포트 중심 브라우저 탭에 오래 열어두기 좋고 구현 난도가 낮다. 변화가 한눈에 보이지 않으면 재미가 약해진다.
초안 추천: 첫 화면은 업무용 운영 대시보드처럼 구성하고, 생명체 표현은 작은 셀, 점, 열지도, 미세한 파형 정도로 제한한다. 이름과 텍스트에서만 군락의 생물성을 드러내면 분위기를 살리면서도 위장성이 생긴다.

저장과 기술 방향

  • 게임과 기획 문서는 각각 독립 HTML 파일로 둔다.
  • 초기 게임은 외부 서버 없이 HTML, CSS, JavaScript만 사용한다.
  • 저장은 localStorage를 우선 사용한다.
  • 저장 데이터는 버전 번호를 포함해 이후 구조 변경에 대비한다.
  • 계정 동기화, 클라우드 백업, 멀티 디바이스 연동은 미래 과제로 둔다.
localStorage는 브라우저와 프로필에 묶인다. 회사 PC, 브라우저 초기화, 시크릿 모드, 정책 설정에 따라 데이터가 사라질 수 있으므로 장기적으로는 내보내기/가져오기 기능이 필요하다.

개발 단계

단계 목표 완료 기준
0. 기획 정리 핵심 루프, 화면 톤, 첫 유전자 후보 확정 이 문서의 미정 항목이 1차로 정리됨
1. 관측 가능한 시뮬레이션 군락 생성 주기, 개체 수명, 자원 변화 구현 HTML을 열면 자동으로 군락 지표가 변함
2. DNA 조작 MVP 수명, 채집, 안정도 관련 유전자 조절 조작 결과가 다음 세대 지표에 반영됨
3. 저장 localStorage 저장과 불러오기 브라우저를 닫았다 열어도 상태가 유지됨
4. 오프라인 진행 마지막 저장 시각 기준 경과 보상 재접속 시 요약 리포트가 표시됨
5. 환경과 위협 상황별 최적 DNA가 달라지는 변수 추가 한 가지 빌드만으로 모든 상황을 압도하지 않음

열린 질문

  • 생명체 표현은 무엇이 좋은가: 세포, 포자, 드론, 미생물, 추상 점군?
  • 군락이 생성하는 객체는 플레이어에게 얼마나 개별적으로 보여야 하는가?
  • 죽음은 단순 제거인가, 아니면 군락에 영양분이나 기억을 남기는가?
  • DNA 조작은 슬라이더형인가, 슬롯형인가, 카드형인가?
  • 업무 화면처럼 보이는 정도와 게임다운 피드백 사이의 균형점은 어디인가?
  • 플레이어가 실패할 수 있어야 하는가, 아니면 성장 속도가 둔화되는 정도가 적절한가?
이 문서는 초기 기획 검토용 초안이다. 구현이 시작되면 게임 HTML과 문서 HTML을 나누고, 문서에는 결정 사항과 변경 이력을 계속 반영한다.
